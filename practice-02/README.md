## 4. Модель данных и функции

Задача — объект с четырьмя полями:

| Поле | Правило |
|---|---|
| `id` | Число, положительное безопасное целое (`Number.isSafeInteger(id) && id > 0`). Строки в число не преобразуются. |
| `title` | Строка; после `trim()` длина от 1 до 100. Записывается очищенная строка. |
| `completed` | `true` или `false`; у новой задачи всегда `false`. |
| `priority` | Строго `"low"`, `"medium"` или `"high"`, по умолчанию `"medium"`. |

**Распределение ответственности между файлами:**

| Файл | Назначение |
|---|---|
| [`src/data.js`](./src/data.js) | Только данные: общий набор `demoTasks`, номер варианта и `variantTasks`. |
| [`src/task-service.js`](./src/task-service.js) | Девять экспортируемых функций и внутренние проверки `validateId`, `normalizeTitle`, `validatePriority`. Нет `console.log` и глобального списка: каждая функция работает только с переданным `tasks`. |
| [`src/main.js`](./src/main.js) | Импортирует данные и функции, выполняет общий сценарий и сценарий варианта, выводит результаты. Деструктуризация используется при выводе сводки: `const { total, completed, pending, progress } = getTaskStats(tasks)`. |
| [`checks.js`](./checks.js) | Готовые 35 проверок и 3 собственные (36–38). |

**Результаты функций:**

| Функция | Успех | Ошибка / отсутствие |
|---|---|---|
| `createTask(id, title, priority)` | `{ ok: true, task }` | `{ ok: false, error }` |
| `findTaskById(tasks, id)` | найденный объект (через `find`) | `undefined` |
| `getPendingTasks(tasks)` | новый массив невыполненных задач (через `filter`) | — |
| `getTaskTitles(tasks)` | новый массив названий (через `map`) | — |
| `getTaskStats(tasks)` | `{ total, completed, pending, progress }`, при пустом списке все поля `0` | — |
| `addTask(tasks, id, title, priority)` | `{ ok: true, tasks: [...tasks, новаяЗадача] }` | некорректные поля (через `createTask`) или повторяющийся `id` |
| `setTaskCompleted(tasks, id, completed)` | `{ ok: true, tasks }`, где `map` + `{ ...task, completed }` | некорректный `id`, не boolean, задача не найдена |
| `renameTask(tasks, id, title)` | `{ ok: true, tasks }`, где `map` + `{ ...task, title }` | некорректный `id`, некорректное название, задача не найдена |
| `removeTask(tasks, id)` | `{ ok: true, tasks }` через `filter` | некорректный `id`, задача не найдена |

**Почему id не равен индексу:** индекс — текущее место элемента в массиве, и после удаления соседних записей он меняется. `id` — постоянный идентификатор задачи. В `demoTasks` задача `id = 4` лежит по индексу `1`, а `tasks[4]` вообще не существует. Поэтому поиск выполняется через `find` по полю `id`.

**Почему getTaskStats возвращает число, а не строку с процентом:** сводка — это данные для дальнейших расчётов (сравнения, проверки, интерфейс в ПР3). `toFixed(1)` возвращает строку и нужен только для отображения, поэтому округление выполняется в `main.js` при выводе. Кроме того, для пустого списка выводится «Задач пока нет», а не процент.

**Какие объекты копируются при изменении задачи:** создаётся новый массив (через `map`) и новый объект **только для изменяемой задачи** (`{ ...task, completed }` или `{ ...task, title }`). Остальные объекты переиспользуются по ссылке без изменений. Входной массив и его объекты не изменяются: `push`, `splice` и присваивания свойствам входных объектов не используются.

## 9. Вывод

По сравнению с ПР1 логика вынесена из отдельных переменных в функции и ES-модули: данные (`data.js`), прикладные операции (`task-service.js`) и демонстрация (`main.js`) разделены. Функции не печатают результат, а возвращают его: объект задачи, массив, сводку или `{ ok, error }`. Поэтому один и тот же модуль используется и в `main.js`, и в `checks.js`, а в ПР3 его можно будет вызывать из обработчиков событий на странице.

Неизменность данных проверена тремя способами: проверками `checks.js` (в том числе с `Object.freeze`), сравнением снимка `demoTasks`/`variantTasks` в конце `main.js` и собственной проверкой 38, где промежуточные версии списка сохраняют своё состояние.

Самым показательным оказался эксперимент 4: новый массив через spread ещё не означает независимые объекты внутри. Поэтому при изменении задачи создаётся не только новый массив, но и новый объект изменяемой записи. Исправленная ошибка — пропущенный `return` в стрелочной функции с фигурными скобками (эксперимент 2).
