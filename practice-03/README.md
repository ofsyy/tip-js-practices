| 1. Отсутствующий элемент и коллекция | `querySelector` → `null`, длина пустого `querySelectorAll` → `0` | `Отсутствующий элемент: null`, `Пустая коллекция: 0` | `querySelector` возвращает `null`, если совпадений нет, — обращение к свойству `null.textContent` вызвало бы ошибку. `querySelectorAll` всегда возвращает `NodeList`, при отсутствии совпадений — пустой, у него можно читать `length`. |

| 5. ## Организация кода

| Файл | Ответственность |
|---|---|
| `src/data.js` | Данные из ПР2: `demoTasks`, `variantNumber = 7`, `variantTasks`. |
| `src/task-service.js` | Девять функций ПР2 без изменений. DOM здесь не используется. |
| `src/task-selectors.js` | `getVisibleTasks(tasks, filter)`: `all` — новый массив `[...tasks]`, `pending`/`completed` — `filter` по `completed`. Входные данные не меняет. |
| `src/task-view.js` | `createTaskElement` строит карточку через `createElement`/`append`, тексты — через `textContent`, без `innerHTML`. `renderTaskList` заменяет дочерние элементы через `replaceChildren(...cards)`, сам `ul` сохраняется. `renderSummary` берёт `getTaskStats` по **полному** списку и отдельно выводит «Показано». `renderEmptyState` различает «Список задач пуст.» и «Нет задач по выбранному фильтру.». |
| `src/main.js` | Состояние: `currentTasks` (полный список) и `currentFilter` (режим отображения). `renderApp` вычисляет выборку и обновляет список, сводку, пустое состояние и активный фильтр. Обработчики `handleTaskListClick` и `handleFilterClick` назначены один раз на контейнеры `#task-list` и `#task-filters` (делегирование). |

**Где что хранится:** полный список — `currentTasks`, фильтр — `currentFilter` в `main.js`; видимая выборка не хранится, а каждый раз вычисляется в `renderApp`. Событие обрабатывается в `handleTaskListClick` (через `closest("button[data-action]")` и `closest("li[data-task-id]")`). Сводка вычисляется функцией ПР2 `getTaskStats(currentTasks)` внутри `renderSummary`.

**Путь одного события:** клик по `span.action-label` → всплытие до `ul#task-list` → `handleTaskListClick` → `closest` находит кнопку и действие → `Number(card.dataset.taskId)` и проверка id → `findTaskById` + `setTaskCompleted` или `removeTask` → при `ok: true` новый массив сохраняется в `currentTasks` → `renderApp()` → `restoreTaskFocus(id, action)`. При `ok: false` выводится сообщение в `#operation-message`, массив не меняется.

## Отладка и клавиатура

**Значения в `handleTaskListClick`.** Точку останова для отчёта ставят на строке `const rawId = card.dataset.taskId;` в `src/main.js` (вкладка Sources). Фактические значения для клика мышью по подписи «Выполнена» у задачи `id = 4` сняты в Console временным наблюдателем на том же `ul#task-list` (в код проекта он не добавлялся):

| Значение | Результат |
|---|---|
| `event.target` | `SPAN.action-label` — вложенная подпись, а не кнопка |
| `event.currentTarget` | `UL#task-list` — контейнер с делегированным обработчиком |
| `event.eventPhase` | `3` — всплытие |
| кнопка через `closest` | `BUTTON[data-action=toggle]` |
| `card.dataset.taskId` | `"4"`, тип `string` |
| `Number(...)` | `4`, тип `number` |
| найденная запись | `{ id: 4, title: "Подготовить модель задач", completed: false, priority: "high" }` |
| результат сервиса | `setTaskCompleted(currentTasks, 4, true)` → `{ ok: true, tasks }`; в новом массиве `id 4` — `completed: true` |
| интерфейс после `renderApp` | статус `id 4` — «Выполнена», сводка 4 / 3 / 1 / 75.0% / 4 |

**Отказ для 777 и 4abc.** У карточки `id = 4` атрибут `data-task-id` временно изменён в DOM:

| Значение атрибута | Действие | Сообщение | Данные |
|---|---|---|---|
| `777` | «Удалить» | `Ошибка: Задача с id 777 не найдена` | без изменений: 4 / 2 / 2 / 50.0% / 4 |
| `4abc` | «Выполнена» | `Ошибка: некорректный идентификатор задачи «4abc»` | без изменений: 4 / 2 / 2 / 50.0% / 4 |

После нажатия «Все» карточки пересоздаются из настоящего массива (`[1, 4, 7, 10]`), сообщение очищается. `Number("4abc")` даёт `NaN`, поэтому строка не превращается в `4` (в отличие от `parseInt`). Клик по названию задачи ничего не изменил.

**Клавиатура** (настоящие нажатия клавиш): `Tab` 10 раз переводит фокус по ссылкам и фильтрам на кнопку «Выполнена» задачи `id 4`. `Enter` — статус «Выполнена», 4 / 3 / 1 / 75.0%, фокус остался на той же кнопке (`aria-pressed="true"`). `Space` — статус снова «В работе», 4 / 2 / 2 / 50.0%, фокус на месте (`aria-pressed="false"`). `Tab` → «Удалить», `Enter` — задача удалена (`[1, 7, 10]`, 3 / 2 / 1 / 66.7%), карточки больше нет, и фокус перешёл на активный фильтр «Все» (`restoreTaskFocus`).

## Вывод

Функции ПР2 подключены к браузерному интерфейсу без изменений: `task-service.js` по-прежнему не знает о DOM, а интерфейс только вызывает его и отображает результат. Карточки строятся DOM-методами, тексты выводятся через `textContent`, поэтому строка с `<strong>` остаётся строкой. Действия обрабатываются одним делегированным обработчиком на `ul#task-list`; кнопка находится через `closest`, поэтому работает клик по вложенному `span`. Идентификатор из `dataset` — строка, он явно преобразуется в число и проверяется, а `4abc` и `777` не повреждают данные.

Главное различие ПР3: **изменение данных и изменение DOM — разные вещи.** Фильтр меняет только `currentFilter` и видимую выборку, полный `currentTasks` остаётся целым. Удаление и смена статуса меняют массив через `removeTask`/`setTaskCompleted`, а DOM затем полностью перерисовывается из массива. Простое `li.remove()` не удалило бы задачу: после следующей отрисовки она бы вернулась. Все 35 проверок сервиса и 36 браузерных проверок пройдены, общий сценарий и вариант 7 совпали с ожидаемыми значениями.
