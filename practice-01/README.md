**Объяснение различия `typeof document`:**

`document` — это объект, который даёт браузер для работы с HTML-страницей. Это часть Browser API, а не самого языка JavaScript. В браузере этот объект есть, поэтому `typeof document` даёт `"object"`. В Node.js HTML-страницы нет, объекта `document` тоже нет, поэтому `typeof document` даёт `"undefined"`. То есть язык один, а среды выполнения разные, и набор доступных объектов у них разный.

**Критерий готовности выполнен:** один и тот же файл работает и в Node.js, и в браузере, различие `typeof document` объяснено.


## Задание 2. Исследование типов и преобразований

**Статус:** выполнено.

Файл `practice-01/js/types.js` запущен в Node.js и в браузере.
Для каждого выражения сначала было предсказано значение и тип,
затем результат проверен через `console.log` и `typeof`.

### Таблица предсказаний и результатов

| № | Выражение | Ожидание до запуска | Фактическое значение | Тип результата | Объяснение |
|---|---|---|---|---|---|
| 1 | `"8" + 2` | `"82"`, string | `82` | `string` | `+` со строкой делает конкатенацию. |
| 2 | `"8" - 2` | `6`, number | `6` | `number` | `-` приводит операнды к числам. |
| 3 | `Number("8") + 2` | `10`, number | `10` | `number` | Явное преобразование. |
| 4 | `"12" > "3"` | `false`, boolean | `false` | `boolean` | Сравнение строк посимвольно: `"1" < "3"`. |
| 5 | `12 === "12"` | `false`, boolean | `false` | `boolean` | Строгое равенство без приведения типов. |
| 6 | `Number("")` | `0`, number | `0` | `number` | Пустая строка → 0. |
| 7 | `Number("text")` | `NaN`, number | `NaN` | `number` | Преобразовать нельзя. |
| 8 | `Boolean("false")` | `true`, boolean | `true` | `boolean` | Непустая строка всегда истинна. |
| 9 | `typeof null` | `"object"`, string | `object` | `string` | Историческая особенность JS. |
| 10 | `typeof NaN` | `"number"`, string | `number` | `string` | `NaN` — число; результат `typeof` — строка. |

### Выводы по заданию 2

1. `+` — единственный оператор, который при работе со строкой делает конкатенацию.
   Остальные (`-`, `*`, `/`) всегда приводят операнды к числам.
2. Автоматическое преобразование типов легко даёт неожиданный результат, поэтому
   числа лучше преобразовывать явно через `Number(...)`.
3. `Number("")` даёт `0`, а `Number("text")` даёт `NaN` — значит, проверка «не NaN»
   не является достаточной проверкой корректного ввода.
4. Строгое равенство `===` не приводит типы: `12 === "12"` всегда `false`.
5. Сравнение двух строк идёт посимвольно: `"12" < "3"`, потому что символ `"1"` меньше `"3"`.
6. `Boolean("false")` = `true`, потому что непустая строка всегда истинна.
7. `typeof` всегда возвращает строку. Поэтому у пунктов 9 и 10 тип результата — `"string"`.
8. `typeof null === "object"` — историческая особенность JavaScript.
   Для проверки на `null` используют `value === null`.

### Правила обработки

1. Оба значения должны быть конечными целыми числами:
   `0 ≤ totalTasks ≤ 1000`, `0 ≤ completedTasks ≤ totalTasks`.
2. При нарушении — одно сообщение `Ошибка: ...`, обычная сводка не выводится.
3. Если `totalTasks === 0` — выводится `Задач пока нет`, процент не считается.
4. Иначе — остаток, процент с одним знаком (`toFixed(1)`), статус.
5. Статус определяется по исходным количествам, а не по округлённому проценту.
