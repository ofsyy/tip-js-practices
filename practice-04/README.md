## Эксперименты с формой и хранилищем

Страница `examples/forms-storage.html`. Значения сняты с поля (`validity`, `validationMessage`) и из журнала страницы.

| № | До запуска: прогноз | После запуска: результат | Объяснение |
|---:|---|---|---|
| 1. Пустое обязательное поле | `submit` не произойдёт, поле невалидно, браузер покажет своё сообщение | Счётчик событий `submit` = `0`, журнал не изменился («Действия ещё не выполнялись.»); `validity.valid = false`, `valueMissing = true`, `validationMessage = "Заполните это поле."` | `required` проверяется браузером **до** события `submit`: невалидная форма не отправляется, поэтому обработчик не вызывается. Это не поломка страницы. |
| 2. Название из пробелов | `required` пропустит, `submit` произойдёт, отклонит прикладная проверка | До отправки `validity.valid = true`; `submit` получен (счётчик `1`), журнал: «submit получен, но прикладная проверка отклонила значение.»; после — `valid = false`, `customError = true`, сообщение «Название не должно состоять только из пробелов.» | Для `required` строка `"   "` непустая. Правило «не пусто после `trim`» — прикладное; `setCustomValidity(message)` делает поле невалидным, а на `input` вызывается `setCustomValidity("")`, иначе поле осталось бы невалидным навсегда. |
| 3. Типы значений `FormData` | `title` — строка, `defaultPrevented = true`, название без краевых пробелов | `submit.defaultPrevented: true`, `typeof FormData title: string`, `typeof localStorage value: string`, `value = { title: "Форма", priority: "high" }` при вводе `"  Форма  "` | `FormData.get` для обычных полей возвращает строки; `preventDefault()` отменил перезагрузку, но обработчик выполнился дальше. Нормализацию (`trim`) делает код. |
| 4. Строка в `localStorage` и JSON | `getItem` вернёт строку, `JSON.parse` — объект | `raw = "{\"title\":\"Форма\",\"priority\":\"high\"}"` (тип `string`), `parsed = { title: "Форма", priority: "high" }` | `localStorage` хранит только строки, поэтому объект сериализуется `JSON.stringify` и восстанавливается `JSON.parse`. |
| 5. Повреждённый JSON | `JSON.parse` выбросит `SyntaxError` | «JSON.parse завершился ошибкой: Expected property name or '}' in JSON at position 1 (line 1 column 2)», `raw = "{broken-json"` | Строка в хранилище может быть любой. Без `try/catch` исключение прервало бы запуск приложения — поэтому `loadTasks` перехватывает его и использует fallback. |

![Эксперимент 3](./screenshots/pr4/1/пр4%20зад%201%20эксперимент%203%20FormData.png)
![Эксперимент 5](./screenshots/pr4/1/пр4%20зад%201%20эксперимент%205%20повреждённый%20JSON.png)

**Итог.** HTML-проверка (`required`, `min`, `step`, `maxlength`) контролирует форму ввода и срабатывает до `submit`. Прикладное правило (пробелы, уникальность id, допустимый приоритет) проверяет код после `submit`. Ошибка разбора — это уже не ввод пользователя, а повреждённая сохранённая строка, она обрабатывается при чтении хранилища.

## Организация кода

| Файл | Ответственность |
|---|---|
| `task-service.js` | Модель задач и неизменяющие операции. Новый `updateTask(tasks, id, title, priority)`: проверяет id и наличие задачи, поля проверяет через `createTask`, но из него берёт только `title` и `priority` — поэтому `completed` редактируемой задачи сохраняется. DOM и storage не используются. |
| `form-validation.js` | Чистая `validateTaskDraft(draft, tasks, editingId)`: явное `Number` для id (пустая строка отклоняется отдельно, иначе `Number("")` дал бы `0`), уникальность при создании, `editingId` при редактировании, `trim` и длина 1–100, приоритет из `low/medium/high`. Возвращает все ошибки полей сразу. `document`, форма и `localStorage` не используются. |
| `task-storage.js` | Граница хранилища: `isValidTaskList` (весь массив, все поля, уникальность id), `loadTasks` (источники `initial` / `storage` / `fallback`), `saveTasks` (оболочка `{ version: 1, tasks }`), `removeSavedTasks` (один ключ). Все обращения к storage внутри `try/catch`. |
| `task-view.js` | DOM карточек, списка, сводки и пустого состояния. Данные и storage не меняет. |
| `main.js` | Состояние (`currentTasks`, `currentFilter`, `editingId`), режим формы `setFormMode`, обработчики `submit`/`click`, координация сервиса, хранения (`persistCurrentTasks`) и отрисовки. |

**Почему `storage` передаётся аргументом.** Модуль явно показывает внешнюю зависимость и проверяется в Node.js объектом-имитацией `MemoryStorage` или объектом, чей `getItem`/`setItem`/`removeItem` выбрасывает исключение (проверки 21, 24, 26) — без браузера и без риска затереть настоящие данные.

**Почему JSON проверяется до использования.** Успешный `JSON.parse` подтверждает только синтаксис. Внутри может оказаться другая версия, `completed: "нет"` или повторяющиеся id; частично корректные данные не используются — весь список заменяется копией исходного набора с предупреждением.

**Поток данных:** `submit/click` → `validateTaskDraft` (для формы) → `addTask`/`updateTask`/`setTaskCompleted`/`removeTask` → при `ok` новый `currentTasks` → `persistCurrentTasks` → `saveTasks` → `renderApp`. `renderApp` хранилище не читает и не пишет; фильтр и `editingId` не сохраняются.

## Вывод

Приложение ПР3 дополнено формой создания и редактирования и сохранением в `localStorage`. Функции ПР2–ПР3 перенесены без изменений (35/35), добавлен `updateTask`, который не сбрасывает `completed`. Проверки новых модулей — 27/27, браузерные — 23/23; общий сценарий и вариант 7 (5 выполнено, 83.3%) совпали с ожидаемыми значениями.

Работают три разных уровня проверки. **Нативная проверка HTML** (`required`, `min`, `step`, `maxlength`) срабатывает до `submit` и не знает модели: строку из пробелов она считает заполненной. **Прикладная валидация** `validateTaskDraft` после `submit` проверяет `trim`, уникальность id и приоритет, а сервисные функции повторяют защиту. **Проверка данных после чтения** в `loadTasks` нужна потому, что строка в хранилище может быть повреждена или иметь другую схему: `JSON.parse` подтверждает только синтаксис, поэтому список проверяется целиком и при ошибке заменяется исходным набором с предупреждением.
